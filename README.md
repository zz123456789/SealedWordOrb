# 缄言珠 / Sealed Word Orb

[English description](publishing/DESCRIPTION.en.md) · [Modrinth](https://modrinth.com/mod/sealed-word-orb) · [CurseForge](https://www.curseforge.com/minecraft/mc-mods/sealed-word-orb)

适用于 **Minecraft Java 1.20.1、Forge 47.4.10（或兼容的后续 47.x）、Java 17**。

本模组的原创源码、资源和文档采用 [MIT 许可](LICENSE.md)，同样适用于已发布的 0.1.0 和 1.0.0。第三方组件保留各自许可，详见 [许可说明](LICENSING.md)。

## 安装与使用

将 `build/libs/sealedwordorb-1.0.0.jar` 放入游戏的 `mods` 文件夹。多人游戏需要客户端和服务端均安装。升级时移除旧版 JAR，不能同时安装两个版本。

1. 在创造模式物品栏的“缄言珠”分类中取出物品，或由管理员执行：
   ```mcfunction
   /give @s sealedwordorb:sealed_word_orb
   ```
2. 创造模式且拥有至少 2 级指令权限的玩家，手持空白缄言珠右键打开编辑界面。主手、副手均可。
3. 输入要执行的指令、权限等级和物品描述。
   - 指令必填，空白或只有 `/` 时不能保存。可带或不带开头的 `/`。
   - 权限等级接受 `0`、`1`、`2`、`3`、`4`，留空为 `2`，不能高于写入者的权限。
   - 描述可留空；留空时封存物品不显示附加描述。描述以普通文字显示。
   - 指令最多 32767 个 UTF-16 字符，描述最多 2048 个，编辑界面为单行输入，长文本可水平滚动。
4. 点击“取消”或按 Esc 不修改物品；点击“保存并封存”后永久锁定编辑。
5. 封存后处于只读状态，所有持有者都可以右键执行指令，包括生存模式的非管理员。对空气、方块或实体右键均可触发。**每颗珠子仅可使用一次，生存和创造模式均会消耗。**

有效封存数据触发一次指令尝试就消耗一颗，即使命令语法错误、权限不足或执行条件不成立也会消耗。封存数据缺失/类型错误时，拒绝执行并保留物品。服务端先移除已使用的珠子，再运行指令，以免 `/give` 或 `/item replace` 生成的新物品被误删。

0.1.0 的既有封存珠及任务奖励无需修改 NBT，升级后也会自动变为一次性。

执行使用珠子中保存的权限等级，而不是持有者自身的等级。执行者是当前持有者，因此 `@s`、相对坐标 `~ ~ ~`、朝向坐标 `^ ^ ^` 和所在维度均以使用者为准。指令执行仅发生在服务端；失败反馈使用 Minecraft 的指令错误消息。

## NBT 格式

三项内容和封存标签保存在物品的 `SealedWordOrb` 子标签中：

```snbt
{SealedWordOrb:{Command:"say 你好",PermissionLevel:2,Description:"向大家问好",Modified:1b}}
```

只要存在 `Modified` 键，即便其值为 `0b` 或其他类型，也不会再打开编辑界面。已封存但内容缺失、类型错误或权限超界的物品会拒绝执行。根标签中的其他数据，例如铁砧自定义名称，会保留。

取消编辑不会写入标记。保存由服务端校验编辑权限、菜单编号、原始手持物品、快捷栏位置和输入内容后完成；重复请求或已失效菜单不会重写珠子。

## 已确认的安全取舍

本版本按需求保留**纯 NBT**，允许复制、赠送及跨存档使用，没有服务端签名或存档绑定。

Minecraft 接受创造模式客户端提交的物品 NBT，恶意创造客户端或 NBT 编辑工具可以伪造珠子、改变权限和指令、移除封存标记。这会绕过本模组编辑界面的权限限制。此风险已经告知并获明确接受，不代表服务端能够证明一颗珠子确由管理员封存。

封存是正常游戏交互中的锁定，不是防篡改加密。持有已经合法封存的高权限珠子，也就获得了执行其中指令的能力。

## FTB Quests 与整合包分发

可以作为 FTB Quests 1.20.1 的物品奖励：先封存一颗珠子，再将其完整物品数据设为奖励。不能只从物品列表选一个不带 NBT 的同名空白珠。任务文件应包含 `item.tag.SealedWordOrb` 内的三项内容和 `Modified`。

分发时包含模组 JAR、FTB Quests 的依赖及 `config/ftbquests/quests/` 任务定义。珠子没有玩家、世界、服务器地址或签名绑定；领取时复制模板，每名玩家得到独立的一次性物品。命令建议使用 `@s` 指向使用者，避免作者账号、旧存档坐标或仅作者存档存在的目标。

详细配置示例、源码核对范围和失效原因见 `FTB_REWARDS.md`。

## 自查与待选改进

具体检查结果见 `SELF_CHECK.md`。以下行为按当前需求保留，可在后续决定是否修改：

- 仅检查指令非空和长度，不预先验证指令语法或目标是否存在。输错的非空指令仍可封存，使用时报告错误；需重新拿一颗空白珠填写。
- 单颗珠子已改为一次性。没有额外冷却；持续按住右键时，如果手中又获得另一颗珠子，仍可能继续使用下一颗。
- 多人服务器的权限插件可能有自己的额外检查；模组使用原版命令权限等级，不承诺绕过其他插件规则。

## 构建与测试

Windows PowerShell 示例（如已配置 Java 17，可省略第一行）：

```powershell
$env:JAVA_HOME='C:\Program Files\Java\jdk-17.0.19'
.\gradlew.bat build
.\gradlew.bat runGameTestServer
```

`build` 生成供普通 Forge 安装使用的重映射 JAR。`runGameTestServer` 在真实 Minecraft 服务端中运行集成测试。测试源码和测试结构位于独立的 `src/gametest`，不打包进发布模组。
